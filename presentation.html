Introduction and Problem Statement

The Context

University campuses generate a high volume of student grievances ranging from infrastructure issues to academic disputes. Currently, most systems rely on manual sorting.

The Core Problems

  • Manual Routing Delays: Human sorting of text complaints creates severe bottlenecks in resolving urgent issues.
  • Lack of Transparency: Students submit complaints but have no visibility into which department is handling them.
  • Misclassification: Without a standardized system, complaints are frequently forwarded to the wrong administrative branch.

"A grievance delayed by manual administrative routing is a grievance denied."

Objectives

1. Automated Categorization

Develop an AI model (Text Classifier) to instantly read, understand, and categorize student complaints into specific departments (e.g., Academic, Hostel, Infrastructure).

2. Seamless Web Integration

Build a robust, three-tier web application allowing secure logins for students to submit issues and admins to manage them.

3. Real-Time Tracking

Implement a centralized dashboard where the status of a grievance is updated and visible to the user immediately.

4. Continuous AI Learning

Create an Admin Feedback Loop allowing authorized personnel to correct misclassified AI predictions, retraining the model for future accuracy.

System Architecture & Design

  • Client Tier (Presentation):
    Responsive HTML templates powered by Jinja2 serving dual dashboards (Student & Admin).
  • Application Tier (Logic):
    Flask framework (`app.py`) managing route handling, session authentication, and invoking the ML script.
  • Intelligence Tier (ML):
    `ai_classifier.py` processes incoming text strings against a pre-trained NLP model to return a departmental prediction.
  • Data Tier (Persistence):
    SQLite database (`grievance.db`) acting as a lightweight, serverless storage solution for atomic commits.

Methodology / Working Process

How a grievance moves from submission to resolution autonomously:

1. Input

Student writes complaint in `submit_complaint.html`

2. Processing

Text sent via POST to `app.py` for routing.

3. AI Classification

`ai_classifier.py` analyzes text and assigns department.

4. Storage

Record saved to `grievance.db` with status "Pending".

5. Resolution

Admin reviews on Dashboard & marks as "Resolved".
